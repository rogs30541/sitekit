# AIGC創客架站套件 架構說明（代號 SiteKit）

## 服務拓撲

```
瀏覽器 ── 同網域 ──> web (Next.js)  ── rewrites /api/* ──> api (NestJS) ──> PostgreSQL（Prisma）
                     │ middleware：301 導向表（每 60 秒從 api 取）                 └─ Redis（P3 佇列，尚未接）
                     │
訂閱制 AI 工具 ── MCP stdio ──> mcp/server.mjs ── Bearer OPS_TOKEN ──> /api/ops/*
```

- `web` 與 `api` 各自部署（Zeabur 兩服務加 postgres、redis 共四個），同網域靠 Next.js rewrites 把 `/api/*` 轉到 api，cookie 同源、不碰 CORS。
- 所有金錢與授權寫入（orders、entitlements、credit_ledger）只有 api 能寫，前端永不直寫資料庫。
- Session 由 api 發 httpOnly cookie（`sk_session`＝隨機 id），狀態與角色以 `sessions` 表為準，登出即失效。web 只轉發 cookie。

## 後台雙路徑

| | MCP 路徑 | AI API 路徑 |
|---|---|---|
| 控制器 | `apps/api/src/modules/ops/ops.controller.ts` | `apps/api/src/modules/admin-ai/admin-ai.controller.ts` |
| 守衛 | `OperatorTokenGuard`（Bearer = `OPS_TOKEN`；未設 token 即整條路徑關閉） | `AdminSessionGuard`（DB session，role 必須是 admin/superadmin；帶 Bearer 直接拒絕） |
| 可做的事 | `OPS_ACTIONS` 全集 | 同一份 `OPS_ACTIONS`，由後台 UI 的 AI 助手代為觸發 |
| 執行層 | `OpsService.run(action, params, actor)` | 同左 |
| 稽核 | `audit_logs.actor = "mcp"` | `audit_logs.actor = "admin-ai:<userId>"` |

規則：**新增任何後台維運功能，先在 `packages/shared` 的 `OPS_ACTIONS` 登記，再在 `OpsService` 實作，兩條路徑自動同時獲得。** 不得為 MCP 或 AI 另寫一套邏輯。

目前動作：`status`、`deploy`（尚未接部署平台，只記稽核）、`migrate`（同上）、`get_settings`、`update_settings`、`import_content`、`adjust_credits`（補點／沖正）、`audit`。

## 課程模組（對齊 Power Course 體驗）

- **章節樹**：`chapters.parentId` 兩層（根層可當單元容器），`order` 為同層排序；後台 ChapterTree 支援拖曳（同層 before/after、拖到根章節右側成子章節）與 ▲▼⇥⇤ 按鈕，整棵樹以 `PATCH /admin/catalog/courses/:id/reorder` 一次寫回（交易）。
- **章節抽屜**：點標題開右側抽屜；「上傳課程內容」選 Youtube 內嵌／Bunny；貼 YouTube 網址 → `GET /admin/videos/resolve?url=`（oEmbed）即時顯示縮圖與標題並順手入影片庫；時長（時分秒）、試看、發布／草稿、章節說明、在單元下新增子章節。
- **教室頁** `/classroom/[slug]/[chapterId]`：左側章節樹（完成勾勾、鎖頭、時長、總進度條、觀看期限），右側自製播放器、觀看進度、標記為已完成／取消、上一個／下一個；`/classroom/[slug]` 導到第一個未完成章節。進度 `chapter_progress`（每人每章一筆），播放每 5 秒回報位置、≥90% 或結束自動完成。
- **封面影片／試看影片**：`courses.coverVideo*`／`previewVideo*` 為銷售頁公開素材（YouTube 自製播放器）；未購買者看試看影片，購買者看「進入教室」。
- **觀看期限**：`courses.accessMode` unlimited／days／until；`OrdersService.markPaid` 依此算 `entitlements.expiresAt`；learn API 的授權檢查含到期，過期即 403，銷售頁與教室顯示到期日。

## AI 工作站與點數（P3 產品化）

- **點數帳本**：`users.creditBalance`（持有）／`creditReserved`（保留），available＝持有−保留。任務建立時 `reserve`（交易內檢查可用）、成功 `settle`（扣持有＋解除保留，ledger `consume`）、失敗／取消 `release`（只解除保留）。ledger 只記持有點數變動（grant／adjust／consume）。管理員與 MCP／AI API 的 `adjust_credits` 可補點或沖正，持有不可為負。
- **Provider 抽象層**（`modules/studio/providers.ts`）：`ImageProvider.generate({prompt,size,quality,apiKey})`；`mock`（本機／CI，SVG 佔位圖、不花錢）、`openai`（Images API）。平台金鑰 `openai.apiKey`（settings 機密）或 env；BYOK 用戶金鑰 AES-256-GCM 加密存 `user_api_keys`，啟用時任務 `byok=true`、不扣點、走 openai。
- **任務狀態機** `ai_jobs`：queued → running → succeeded | failed；queued 可 canceled。程序內序列佇列（重啟時 running 退回 queued 並補跑）；接上 Redis 後可換 BullMQ 而不動狀態機。結果檔寫 `storage/ai/`（`STORAGE_DIR`），經 `/api/assets/*` 靜態服務；正式環境換 R2。
- **模板** `ai_templates`：公開端只回名稱、欄位、點數（**不回 systemPrompt、不回成本／毛利**，避免 inShow 的外洩問題）；後台 CRUD 可見 systemPrompt。
- **頁面**：`/studio`（點數卡、模板庫、動態表單、標準／印刷、任務列表輪詢、下載）、`/member`（點數與明細、BYOK 金鑰）、`/admin/studio`（模板 CRUD、點數調整、任務與成本列表）。

## 課程影片來源（YouTube 隱藏來源）

- 章節 `videoProvider` 預設 `youtube`，`videoProviderId` 存影片 ID；後台「課程管理 → 章節與影片」從影片庫選單綁片。建議影片設「不公開」。
- 公開目錄 API 與 SSR HTML 只回 `hasVideo` 布林，永不回傳來源與 ID；ID 只在 `/api/learn/play/:chapterId` 授權檢查通過後回給前端。
- 前端 `YouTubePlayer`：IFrame API＋youtube-nocookie、`controls=0 rel=0 iv_load_policy=3 disablekb=1`，iframe 設 `pointer-events:none`，所有操作走自製控制列；未播放／暫停／結束以不透明遮罩＋自家海報蓋住 YouTube 介面；封鎖右鍵。
- **誠實邊界**：DevTools 仍可在 iframe src 看到影片 ID，這是平台天性；要完全隱藏來源請切 `bunny` 自架。

## 開發模式鐵律

- `apps/api` 開發與建置一律走 `nest start --watch` / `nest build`（tsc）。**不可用 tsx／esbuild 直跑**：esbuild 不產生 `emitDecoratorMetadata`，Nest 建構子注入會拿到 undefined，任何有相依的 controller 都回 500（骨架期實測踩到）。
- **dev server 跑著時不可跑建置**：`nest build`（deleteOutDir）會清 dist 讓 `nest start --watch` 撞 MODULE_NOT_FOUND 而死；`next build` 會打壞 dev 的 `.next`。要建置先停 preview。
- api 啟動時若 cwd 有 `.env` 會用 `process.loadEnvFile` 載入（不覆蓋既有變數）；正式環境由平台注入，`DATABASE_URL` 必填、缺了直接不啟動。
- 本機免 Docker 資料庫：`npm run dev:db` 直接驅動 `@embedded-postgres` 的 initdb／pg_ctl／postgres。**Windows 陷阱**：專案路徑含中文（cp950）時 initdb 會炸 `invalid byte sequence for encoding UTF8`，所以二進位與資料目錄一律放 ASCII 路徑（`%LOCALAPPDATA%/sitekit`），且 `fs.cpSync` 複製大量 exe/dll 會無聲退出，改用 robocopy／cp。
- 測試時若用 git-bash 的 curl 送中文 JSON，payload 會以 cp950 送出而變亂碼；驗中文請走瀏覽器或 PowerShell `-Encoding utf8`。

## 金流鐵律（從度哥繼承）

1. 授權欄位永不開放前端寫入：`entitlements`、`orders` 只在 api 的 `OrdersService.markPaid` 內寫。
2. 付款以伺服器端驗證為準：`/api/payments/:provider/notify` 由各 adapter 驗章（藍新 TradeSha＋CheckCode、綠界 CheckMacValue、統一 HashInfo＋AES-GCM）或向金流商 API 確認（LINE Pay Confirm、支付連回查訂單），再由 PaymentsService 比對金額，通過才 `markPaid`；`ReturnURL` 導回只重複同一段處理再轉到 `/order-result`，頁面本身只輪詢狀態。adapter 只負責「驗證與解讀」，不得自行寫入授權。
3. 回呼冪等：同 orderId＋provider＋type＋tradeNo 的 `payment_events` 不重複寫；`markPaid` 對已 paid 直接回傳；LINE Pay 已 paid 的訂單不再 Confirm。
4. 媒體網址即時簽發、帶時效：Bunny token 1 小時，`/api/learn/play/:chapterId` 先驗授權（或試看）。
5. 本機用 `payment.provider=mock`（非 production 才允許），假閘道回呼以 HMAC(SESSION_SECRET) 簽章，任意呼叫會被拒。

新增遷移的方法（`migrate dev` 在非互動環境不可用）：`prisma migrate diff --from-url $DATABASE_URL --to-schema-datamodel prisma/schema.prisma --script > prisma/migrations/<ts>_<name>/migration.sql`，再 `migrate deploy`。
