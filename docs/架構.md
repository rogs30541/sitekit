# SiteKit 架構說明（v0.1 骨架）

## 服務拓撲

```
瀏覽器 ── 同網域 ──> web (Next.js)  ── rewrites /api/* ──> api (NestJS) ──> PostgreSQL / Redis
                                                              │
                     訂閱制 AI 工具 ── MCP stdio ──> mcp/server.mjs ── Bearer OPS_TOKEN ──> /api/ops/*
```

- `web` 與 `api` 各自部署（Zeabur 兩服務加 postgres、redis 共四個），同網域靠 Next.js rewrites 把 `/api/*` 轉到 api，cookie 同源、不碰 CORS。
- 所有金錢與授權寫入（orders、entitlements、credit_ledger）只有 api 能寫，前端永不直寫資料庫。

## 後台雙路徑

| | MCP 路徑 | AI API 路徑 |
|---|---|---|
| 控制器 | `apps/api/src/modules/ops/ops.controller.ts` | `apps/api/src/modules/admin-ai/admin-ai.controller.ts` |
| 守衛 | `OperatorTokenGuard`（Bearer = `OPS_TOKEN`；未設 token 即整條路徑關閉） | `AdminSessionGuard`（HMAC 簽章 cookie，role 必須是 admin/superadmin） |
| 可做的事 | `OPS_ACTIONS` 全集（status、deploy、migrate、settings、import） | 同一份 `OPS_ACTIONS`，由後台 UI 的 AI 助手代為觸發 |
| 執行層 | `OpsService.run(action, params, actor)` | 同左 |
| 稽核 | `actor = "mcp"` | `actor = "admin-ai:<userId>"` |

規則：**新增任何後台維運功能，先在 `packages/shared` 的 `OPS_ACTIONS` 登記，再在 `OpsService` 實作，兩條路徑自動同時獲得。**
不得為 MCP 或 AI 另寫一套邏輯。

## 路由分組（apps/web/app）

| 分組 | 路徑 | 渲染 |
|---|---|---|
| (marketing) | `/`、`/about` | 預渲染（SEO） |
| (shop) | `/store` | ISR |
| (learn) | `/courses` | 登入後 SSR |
| (studio) | `/studio` | CSR 工作站 |
| (account) | `/member` | SSR |
| (admin) | `/admin` | SSR + 角色守衛（獨立 layout，之後拆獨立 chunk） |

## 資料模型（apps/api/prisma/schema.prisma）

users、identities、products、courses、chapters、orders、order_items、entitlements、credit_ledger、ai_jobs、contents、redirects、settings、audit_logs。

## 分期

依 `docs/全新網站規劃.md` 第 07 節四階段。本版為 P1 之前的骨架：可安裝、可建置、可跑健康檢查與雙路徑示範。

## 開發模式鐵律

- `apps/api` 開發與建置一律走 `nest start --watch` / `nest build`（tsc）。**不可用 tsx／esbuild 直跑**：esbuild 不產生 `emitDecoratorMetadata`，Nest 建構子注入會拿到 undefined，任何有相依的 controller 都回 500（骨架期實測踩到）。
